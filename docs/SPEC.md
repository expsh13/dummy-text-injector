# Dummy Text Injector 仕様書

## 概要

Webページのレイアウト崩れテスト用Chrome拡張機能。
ページ内の要素テキストを任意のダミーテキストに差し替え、文字数の違いによるレイアウト崩れを確認できる。

## 背景・課題

- 現状はDevToolsで要素を手動編集してテキストを差し替えている
- 複数要素のテスト、文字数指定、元に戻す操作が面倒
- 既存ツールは「生成してコピペ」か「フォーム要素のみ」で、通常のDOM要素を直接ターゲットにして文字数指定で差し替えるものがない

---

## 機能仕様

### 1. 選択モード

#### 1.1 アクティベーション
- ツールバーアイコンのポップアップからON/OFF切り替え
- ONにするとページ上で要素選択が可能になる
- バッジに「ON」表示

#### 1.2 要素ホバー
- マウスホバー時、**テキストを持つ要素のみ**に青枠ハイライトを表示
- テキストを持たない要素（ラッパーdiv等）は無反応
- カーソルがcrosshairに変化

#### 1.3 テキスト要素の判定条件
以下のいずれかを満たす要素を「テキスト要素」とする:
- 直接の子テキストノードに空白以外の文字がある
- `<input>`（type=text, search, email等のテキスト系）
- `<textarea>`
- `contentEditable`な要素

以下は除外:
- `<script>`, `<style>`, `<meta>`, `<link>`, `<br>`, `<hr>`, `<img>`, `<svg>`
- `<input type="checkbox|radio|submit|button|file|image|reset|hidden">`
- パネル自身の要素

> **注**: iframe内の要素、およびターゲットページ内のShadow DOM（Web Components）内部の要素はv1では対象外とする。

#### 1.4 クリック選択
- クリックでテキスト要素を選択（橙枠ハイライト）
- 選択モード中はクリックイベントのデフォルト動作を抑制（`preventDefault` + `stopPropagation`）するため、ページ内のリンク・ボタン等は操作不能となる（意図的な仕様）
- 単体クリック: 既存の選択をクリアして1つだけ選択
  - ただし、3要素以上選択中の場合はクリア前にステータスバーで確認UIを表示
    - ステータスバーに「N個の選択をクリアしますか？」メッセージ＋「クリアして選択」「キャンセル」ボタンを表示
    - 確認UIは自動消去しない（ユーザー操作またはEscキーで閉じる）
    - 「クリアして選択」→ 既存選択クリア＋新規選択、「キャンセル」→ 何もしない
- **Cmd+クリック（Mac）/ Ctrl+クリック（Win）**: 複数選択（トグル動作）
  - 未選択要素 → 選択に追加
  - 選択済み要素 → 選択から除外

#### 1.5 選択解除・モード終了
- **Escキー**:
  - 要素が選択中の場合: 選択をクリア（モードは維持）
  - 選択なしの状態で押下: 選択モードをOFF
- パネルの閉じるボタンで選択モードOFF
- **モードOFF後の状態保持**:
  - 変更済みハイライト（緑点線）は維持される
  - Undoストアは保持され、モード再ON時に利用可能
  - ページリロードまたはSPA遷移（URLの変更を伴うもの）でUndoストア・ハイライトはクリアされる

### 2. テキスト差し替え

#### 2.1 文字数指定モード
- 数値入力で文字数を指定（1〜10000）
- 指定文字数のダミーテキストを生成して要素に適用
- ダミーテキスト: ひらがな五十音の繰り返しで生成

#### 2.2 プリセットモード

##### ビルトインプリセット

| カテゴリ | プリセット名 | テキスト |
|---------|------------|---------|
| 日本語 | 極短（6文字） | ダミーテキスト |
| 日本語 | 短（1文） | 吾輩は猫である。名前はまだない。 |
| 日本語 | 中（2文） | 吾輩は猫である。名前はまだない。どこで生れたかとんと見当がつかぬ。何でも薄暗いじめじめした所でニャーニャー泣いていた事だけは記憶している。 |
| 日本語 | 長（段落） | 吾輩は猫である。名前はまだない。どこで生れたかとんと見当がつかぬ。何でも薄暗いじめじめした所でニャーニャー泣いていた事だけは記憶している。吾輩はここで始めて人間というものを見た。しかもあとで聞くとそれは書生という人間中で一番獰悪な種族であったそうだ。 |
| Lorem | Short | Lorem ipsum dolor sit amet. |
| Lorem | Medium | Lorem ipsum dolor sit amet, consectetur... (3文) |
| Lorem | Long | Lorem ipsum... (フルパラグラフ) |
| データ | 電話番号 | 090-1234-5678 |
| データ | メールアドレス | example@example.com |
| データ | URL | https://example.com |
| データ | 日付 | 2024年1月1日 |
| データ | 氏名 | 山田 太郎 |
| データ | 住所 | 東京都渋谷区渋谷1-1-1 |

##### カスタムテキスト入力（v1）
プリセットドロップダウンに「カスタム」オプションを提供する。選択時にテキスト入力欄が表示され、ユーザーが任意のテキストを都度入力して適用できる。入力テキストは保存されない（都度入力）。

##### ユーザー定義プリセット（v1.1予定）
> ユーザーが名前付きでプリセットを登録・編集・削除できる機能。ブラウザ間同期を含む。v1.1で実装予定。カスタムテキスト入力（上記）とは異なり、名前を付けて保存・再利用できる。

#### 2.3 テキスト適用
- 選択中の**全要素**に同じテキストを一括適用
- 要素タイプ別の処理:
  - `<input>` / `<textarea>`: `.value`を設定し、`input`・`change`イベントを発火
  - `contentEditable`: `.textContent`を設定（リッチフォーマットは失われる）
  - **通常要素**: 直接の子テキストノードのみを置換する。子要素（`<span>`, `<small>`等）は保持される
    - 例: `<h2>Title <small>sub</small></h2>` → `<h2>ダミーテキスト <small>sub</small></h2>`
- 適用された要素には変更済みハイライトを表示

---

### 3. Undo（元に戻す）

#### 3.1 元テキストの保存
- テキスト適用前に、要素の元テキストを自動保存
- 同じ要素に複数回適用した場合でも、**最初の元テキストのみ保持**（チェーン修正対応）
- 元テキストの管理には`WeakMap`を使用し、DOMから削除された要素は自動的にGC対象となる
- SPA遷移（URLの変更を伴うもの）時、Undoストアはクリアされる

#### 3.2 個別Undo
- 「選択を元に戻す」ボタン: 現在選択中の要素を元テキストに復元

#### 3.3 全リセット
- 「全てリセット」ボタン: 変更した**全要素**を元テキストに一括復元

### 4. UI

#### 4.1 ツールバーポップアップ
- 選択モードON/OFFトグルボタン

#### 4.2 フローティングパネル
選択モードON時にページ上に表示されるパネル。

**構成:**
- ヘッダー: タイトル「Dummy Text Injector」+ 最小化ボタン + 閉じるボタン、ドラッグ移動可能
- 選択情報: 選択中の要素数とタグ名
- モードタブ: 「プリセット」/「文字数指定」切り替え
- プリセットモード: ドロップダウン（ビルトイン + カスタム入力）
- 文字数指定モード: 数値入力 + プレビュー表示
- 適用ボタン
- Undoコントロール: 「選択を元に戻す」「全てリセット」
- フッター: 状態表示

#### 4.3 プリセット管理画面（v1.1予定）
> ユーザー定義プリセットの管理画面。新タブで開く独立ページとして、プリセットのCRUD（追加/編集/削除）を提供する。v1.1で実装予定。

## 技術要件

- **Manifest V3**
- **パーミッション**: `activeTab`, `scripting`（`storage`はv1.1でユーザー定義プリセット実装時に追加）
- **Content Script注入**: ポップアップからの`chrome.scripting.executeScript`によるオンデマンド注入（`content_scripts`による自動注入は使用しない）
- **パネルDOM分離**: Shadow DOM（`mode: 'open'`）
- **バッジ制御**: Content Scriptから`chrome.runtime.sendMessage`でService Worker（background.js）に依頼し、Service Workerが`chrome.action.setBadgeText`を呼び出す（`chrome.action` APIはContent Scriptからは直接利用不可のため）

---

## 制限事項（v1）

- **iframe**: iframe内の要素は選択・操作の対象外
- **Shadow DOM**: ターゲットページ内のShadow DOM（Web Components）内部の要素は対象外
- **SPA遷移**: URL変更を伴うページ遷移時、Undoストアとハイライトはクリアされる
- **CSSの干渉**: ホスト側CSSの`!important`ルールによりハイライト表示が影響を受ける可能性がある
- **outlineの上書き**: ハイライトに`outline`プロパティを使用するため、ターゲットページが要素に設定している`outline`が一時的に上書きされる
